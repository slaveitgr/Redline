# Overlay and game launch controls

Performance > Metrics > Overlay now configures 12 MangoHud metric flags, Compact/Balanced/Detailed profiles (manual changes become Custom), horizontal layout, an allowlisted in-game toggle hotkey, font, position, background opacity and a global FPS limit. Metrics visibility inside the Redline window is independent of the in-game overlay. Unsupported sensor values remain dependent on MangoHud/driver availability.

The Preferences overlay switch and Settings > Hotkeys use the same saved keys as Performance. Configuration directives are validated, bounded, generated by one serializer and written atomically. Every metric flag is written as 0 or 1 to avoid inheriting unwanted defaults. Errors saving the configuration are reported through GamingTools.message.

The MangoHud FPS limit applies to all game launches using Redline's shared configuration. Gamescope has a separate per-game limit connected to `gamescope -r` in generated launch options. If both limiters are enabled, both apply; users should normally choose one. The Gamescope selector is disabled unless that game's runtime exposes Gamescope. Windows Radeon Chill is not claimed as implemented.

Configuration takes effect on the next game launch. This pass does not inject an overlay into already running games, edit Steam while it runs, install dependencies, or change drivers. Preview configuration remains isolated from the user's normal game configuration.

Validation: native preview suite, tests/test_overlay_configuration.cpp for explicit metric flags, limits, layout, hotkey, input validation and persisted configuration; existing preview isolation check. No real game FPS/latency benchmark was performed.

Directive reference: https://github.com/flightlessmango/MangoHud/blob/master/data/MangoHud.conf (also checked against the installed Steam Snap example).
